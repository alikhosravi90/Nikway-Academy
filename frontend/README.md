# Local operational academy frontend

Recovered React/Vite visual identity and local Noto font are retained. The recovered source prototype is in `prototype/`; its 37 manifest files were verified against architecture phase-1–2 evidence before recovery. Three files subsequently received publication privacy redactions of personal display names and matching test selectors; the current manifest records these changes explicitly. The operational application is `src/` and does not import the prototype, Dexie or mock tutor.

The browser authenticates with Keycloak realm `academy`, public client `academy-web`, PKCE S256, default `http://localhost:18480`. Tokens remain in keycloak-js memory. Identity, tenant and permissions are verified by the API; frontend role display is not an authorization boundary. Requests use `/api` with bearer tokens; nginx proxies to `api:8000`. No service worker caches private API responses. Learning mutations require network access. Historical prototype remains local-only and is not published in the production build.

`npm ci && npm run build` validates types and builds static files. Docker builds this application with the supplied Dockerfile and nginx configuration. Compose should bind host loopback port 18401 to container port 80. Use `localhost` consistently with the configured OIDC redirect origin. Set `VITE_AUTH_URL` during a custom build only when the approved issuer changes.

`npm run test:e2e` runs real browser integration journeys. Provide `E2E_LEARNER_USERNAME`, `E2E_LEARNER_PASSWORD`, `E2E_REVIEWER_USERNAME`, and `E2E_REVIEWER_PASSWORD` through runtime environment; never commit them. `E2E_CREDENTIALS_FILE` can instead point to the generated runtime credentials JSON (default `../infra/runtime/credentials.json`, entries `learner-a` and `reviewer-a`). `BASE_URL` defaults to `http://localhost:18401`. Tests skip explicitly without credentials. They create synthetic learning submissions in the configured local tenant and require a seeded course. No API or auth mocks are used. Reviewer test expects learner test evidence. Existing unit tests in `prototype/tests` validate only the preserved historical prototype.

Services screen displays the live capabilities response. No model, Moodle, BBB or other external service is represented as working unless the API reports it. Full WCAG conformance and production readiness are not asserted.
