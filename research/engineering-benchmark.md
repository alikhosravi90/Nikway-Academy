# Learning platform engineering benchmark

Status: preliminary qualitative benchmark; no source-code audit or runtime verification.

| Reference | Candidate pattern |
|---|---|
| [Open edX](https://github.com/openedx/edx-platform) | Modular architecture and authoring/delivery separation |
| [Frappe Learning](https://github.com/frappe/lms) | Lightweight MVP and local development |
| [Moodle](https://github.com/moodle/moodle) | Plugins, peer review and quality gates |
| [Canvas](https://github.com/instructure/canvas-lms) | Institutional learning workflows |
| [Discourse](https://github.com/discourse/discourse) | Community participation |
| [BigBlueButton](https://github.com/bigbluebutton/bigbluebutton) | Interactive workshops |
| [Kolibri](https://github.com/learningequality/kolibri) | Offline learning and contributor guidance |
| [H5P](https://github.com/h5p) | Interactive content |

## Proposed engineering roadmap
0. Repository governance and licensing
1. Product discovery and requirements
2. Validate twelve architecture documents
3. Technology feasibility and licensing review
4. Development environment and CI/CD
5. Interactive prototype
6. Operational core
7. Learning modules
8. Service integration
9. AI agents
10. Security, quality and capacity tests
11. MVP release
12. Continuous improvement

## Validation backlog
For each reference capture pinned revision, license, architecture, repository structure, contribution process, CI, tests, security policy, deployment and offline behavior. Run reproducible feasibility tests before adoption. No ranking or compatibility claim is verified.
