# Documentation standard

Use stable kebab-case paths, English canonical technical text, optional Persian translations, UTF-8 Markdown. Each new normative document must declare ID, title, version, status, owner role, scope, dependencies, decisions, acceptance criteria, references and change history. Status vocabulary: proposed, reviewed, accepted, superseded. Implementation status and verification status are separate. Use ADRs for conflicts and explicit supersession; never delete historical evidence merely to simplify navigation. Link evidence to commit and environment; distinguish reported from independently reproduced results. Public repository must contain no secrets or personal data. Changes require issue, review and validation. Existing documents require migration to this template; this standard does not claim they already comply.
