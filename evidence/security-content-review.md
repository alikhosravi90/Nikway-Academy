# Independent content admission review

Date: 2026-11-25. Result: **PASS — bounded local content admission**, not release approval or Content Factory service interoperability.

The reviewer inspected `backend/app/content_api.py`, `backend/app/main.py` and migration `003_content_packages.py`, then ran `evidence/security-content-independent.py` against the real candidate API, PostgreSQL and Keycloak using authorization-code PKCE sessions. The candidate used loopback API 18600, UI 18501 and IdP 18580. No external service or mocked authentication was used. The pre-existing service on 18500 was not altered.

## Observations and fixes verified

- The initial catalog INSERT grant inherited tenant-only RLS and allowed a learner DB context to insert same-tenant courses. The API owner added restrictive active-reviewer INSERT policies to courses and lessons. The independent live test confirms learner INSERT is rejected.
- The default 20 KiB request limit conflicted with the documented 10,000-character Persian assessment limit. The API owner added a bounded 64 KiB submission stream limit. A 10,000-character Persian payload passed; 10,001 characters failed validation.
- Contract validation now rejects NUL text and oversized version strings before PostgreSQL JSONB/index operations. Independent live negative tests returned 422.
- The API owner's concurrency test exposed event-loop blocking when synchronous PostgreSQL advisory locking ran inside the async import handler. The owner moved validation and admission work to a threadpool. The independent run then confirmed four concurrent imports and four concurrent publications each produced exactly one effect and three replays.
- Publication uses serialized access, expected digest/revision checks and a transaction that completes before the response. Published package updates are filtered by RLS; content columns have no UPDATE grant. Source package IDs are not runtime tenant authority; runtime course IDs derive from trusted tenant and package/version identity.
